# 渲染端设计说明（src/，翻译栈除外）

代码：`src/components/`、`src/stores/`、`src/floating/`、`src/document/`、`src/ai/`、`src/config/`、`src/core/`、`src/tts/`、`src/translation/`、`src/ocr/`、`src/listen/`、`src/i18n/`。翻译栈见 `stack.md`，IPC 与预加载见 `ipc.md`。这里记「为什么这样写」与踩过的坑；代码里只留指针。

## 1. 主窗口与翻译面板

- **栈客户端**（`translation/stack-client.js`）：与旧的 `services/translation.js` 单例同名 API，编排层只换一个 import。`privacyMode / useCache` 从这个面上**消失**：主进程门面每次请求读当前模式并注入，调用点再也削弱不了安全 / 离线模式；`stripPrivacy()` 是双保险，顺带丢掉 AbortSignal 这类不可克隆字段（否则 IPC invoke 会炸）。每扇窗一个全局 chunk 监听器，帧按 streamId 路由；帧可能早于 streamStart 的 invoke 返回（门面立刻启动异步流水线），未知流的帧先短暂缓冲。`supersede`（默认开）：本窗口新流中止旧流，翻译面板只显示一个结果正合适；听译字幕是许多条并行的独立行，传 `supersede: false` 不碰活动流槽。第三参数 privacyMode 为了兼容仍接受但永不发送。就绪判断没有桥（浏览器开发态）时诚实地答「未知」，未知不能当问题显示。
- **主窗口翻译服务**（`translation/main-translation.js`）：历史门读门面附在每个结果上的 `effectivePrivacyMode` 快照，门永远不会与请求实际运行的模式不一致。被取代的运行（清空或重译）不碰 UI、不写历史。OCR 在主进程栈里跑，这边只转发图片与首选引擎；视觉引擎回退要浮出提示，硬锁（连续失败禁用）与软回退（模型不支持视觉）两种措辞，锁标志随结果带回。`understand` 类的行是解释不是翻译，计数器不算它（store 侧 addToHistory 同样过滤）。
- **翻译面板**（`components/TranslationPanel/`）：`useShallow` 选片，流式每次刷新不再重渲整个面板。AI 动作读**源文**侧，入口跟随源文框而不是有没有译文；截图只在源文框仍持有它识别出的文字时代表源文，编辑或粘贴即退役。OCR 写入源文后不显式触发翻译：写入会用新闭包重新触发防抖自动翻译（正确的 `ocr` 模板 + 覆盖层通知），从本次渲染的旧 handleTranslate 延迟调用两样都会漏。防抖自动翻译在定时器里重查状态，快速编辑再清空不会发出过期的翻译。闭包安全的重入守卫：流式期间 Ctrl+Enter 与模板点击没有禁用，并发流会交错。`navigator.onLine` 不可靠且本地源无网也能用——只警告，让请求自己决定。S-2 后记：简洁 / 完整切换在这里试过又当天回退（藏两个图标不值一个模式开关，语气模板配得上位置，用户裁定），MT 徽章的移除留下了。提示气泡一次一个且只在有译文可操作时出现：指向死控件的提示会教会用户忽略提示。词汇表替换 toast 5 s 关闭、悬停暂停；渲染槽无 key 且跨翻译保持真值，新替换落到同一个已挂载实例上，每批重新计时。
- **保存 / 风格改写**（hooks）：分析用代计数——被关闭或被取代的模态里慢回来的 LLM 回复不能覆盖新分析的字段再被保存。术语检查三级替换：整词精确 → 术语中任一单词 → 复制到剪贴板手动；「不再提示」持久化在收藏项本身，跨重启与导入导出。只对短术语检查，多句词条误报太多。
- **主窗口壳**（`components/MainWindow/`）：窄选择器——流式每秒改几十次 `translatedText`，窗口壳不能跟着重渲。各页签首次访问才挂载、之后常驻，文档翻译进度等在途状态不丢。「用 T-Translate 打开」的监听器放在这里而不是 DocumentTranslator：那个页签可能还没挂载。静默截图链（Alt+Q）不显示主窗口，引擎中途降级的提示要随文本一起送到划词窗——这条链不会显示主面板上的回退横幅。装配提示只出现在新用户落地的面板：每个页签都重复一条会像警报而不是提醒。历史自动删除的控件早于 0.2.9 存在但一直没有实现，现在在这里。
- **App.jsx / main.jsx**：`window.__appLanguages` 仍然承重——悬浮窗的 GET_SETTINGS 在主窗口存在时经 `executeJavaScript` 读它。v0.3.1 栈迁移后孤立的 localStorage 键在主窗口启动时退役（L2 缓存可丢弃、冷重建 D-2b；自定义过滤器搬到 electron-store 由栈读取 D-1b），所有窗口同源，主窗口跑一次即可。主题优先级 settings store > localStorage，解析后的值镜像回 localStorage，刷新时 React 挂载前就画对主题。OCR 引擎从 electron-store 播种（唯一来源）——它不再持久化在 zustand 键里，否则主窗口每次启动重置为默认引擎并与悬浮窗读到的分叉。理解类结果以自己的 kind 到达，丢掉标记会把它们静默归档成翻译。渲染期错误归 ErrorBoundary（`main.jsx` 包着 `<App/>`）：以前这里的 try/catch 破坏 hook 顺序，挂载时抛错渲染出没有标题栏的兜底——无边框窗没有拖拽区。主题没有 `auto` 分支：从没有东西写 theme='auto'，未知值回落 light 而不是没有匹配的 data-theme。渲染端不能也不该直接连任何端点（webSecurity 开着），调试面都经主进程栈。

## 2. 翻译 store 与持久化（stores/）

- 语言码守卫只为拒绝垃圾（旧配置里过期的码、IPC 传错），不为守门目录：用户自加的语言是合法选择，只对内置表校验曾在选中的一瞬间把它们全部丢掉。
- zustand persist 每次 setState 都把 partialize 后的状态（单历史就可能 1000 条）重新序列化：每次按键、流式时每次刷新。stringify + 写盘要节流，beforeunload 兜尾。Immer 快照不可变，持有最新引用是安全的。
- 加密保险库（主进程 DPAPI 文件）在桥存在且加密可用时承载 blob；localStorage 仍是 vitest / 无头运行与无 DPAPI 机器的兜底。标志在 getItem 里解析——zustand 总是先 hydrate 再第一次 setItem。写失败只留在内存，下次节流写重试，**永不回落明文**。一次性迁移：加密副本确认落盘后明文才离开 localStorage。Electron 里 hydration 变成异步（约 10 ms IPC），Electron 外仍是同步 localStorage（测试就靠这个播种）。
- `subscribeWithSelector` 必须有：`sync-to-electron.js` 用 (selector, listener, options) 订阅，没有这个中间件，原生 subscribe 把 selector 当 listener，整个同步层静默失效。sync-to-electron 是 `settings.translation.sourceLanguage / targetLanguage` 的唯一同步点；启动时对账一次——subscribe 只在**变化**时触发，防抖写丢失（100 ms 内退出）会让镜像永远过期；每个语言字段分开写，不覆盖 `translation.providers` 这类兄弟字段；页面卸载前冲掉待写。
- **安全模式往返**：进入时把历史 / 统计藏起来、用空的跑；退出时恢复，安全模式的条目永不渗入持久历史。藏匿必须随「安全模式下退出」一起持久化，否则落盘的是清空后的历史、真数据重启后不可恢复。清空历史要连藏匿一起清，否则「已清空」的历史在离开安全模式时悄悄复活。安全模式下导入会被藏匿恢复静默丢弃，UI 禁用按钮、store 再守一次。
- **0.3.x 空翻译 bug 的遗产**（`history-sanitize.js`）：栈曾在模型回空时把整个结果对象 `{text:"",from,to}` 当译文返回，v0.3.4 在缓存层堵住且缓存条目自愈，但 addToHistory 已经把对象写到磁盘，那里没人修。把非字符串当 React 子节点渲染会抛 #31，一行坏数据拖垮整个面板。两种形状两种策略：历史是自动记录的，救不回来的行不是数据而是本不该记的失败翻译——丢；收藏是用户整理的，永不静默删除——把不可用字段置空、保留行。读入时修复（这些条目在 localStorage 里，别处永远没机会修），写入侧 `toStoredText` 而不是 `|| ''`——对象是真值会直接落盘。`HighlightText` 是最后一道防线。
- 收藏 id：展开顺序让 uuidv4 只是兜底，调用方给的 id 优先；没有 id 的条目（词汇表导入 bug）永远删不掉——removeFromFavorites 按 id 过滤；读入时给无 id 的行补 id。收藏按 (sourceText, targetLanguage) 去重，同一个词可以存中文和法文两种译法。
- **词汇表不是一个语言对**：把所有条目都交给翻译会替换成恰好排在前面的那个，把中文塞进法文输出。所以排除其他目标语言的条目；同一个词既有本语言匹配又有无语言条目时匹配优先；无语言条目（导入的文件不带语言）仍可用，丢掉会静默弄坏每一份导入的词汇表。
- 版本：风格改写与用户编辑作为独立版本，重复的折叠（第二次改写覆盖已有的风格版本）。清空时 id 置 null，在途的流会通过身份检查失败而不是把文字复活到已清空的面板。
- AI 结果挂在它派生自的翻译上——摘要不是自己的历史条目，是那条翻译「也有」的东西；按源文匹配因为三扇窗没有共享的翻译 id；挂不上就不写（结果留在自己窗口里当一次性的）。每个动作一个结果、最新覆盖，与风格版本同一折叠规则。理解类条目留在翻译计数器之外——「翻译次数」算上解释就是撒谎；重新解释同一段替换旧笔记而不是堆近似重复的行；去重按 kind 分域，翻译不能挡住解释。恢复解释类条目只回填源文，目标框不会把它当译文呈现。
- `ocrStatus.engine` 故意不持久化：`settings.ocr.engine`（electron-store）是唯一来源，启动时播种；两边都持久化曾导致分叉。'strict' 模式 0.2.9 删除，映射到 offline。partialize 只保留 `{engine}`，运行字段恢复默认；语言只持久化，永不恢复在途翻译文本。
- `getPrivacyOptions()` 曾住在这里，v0.3.1 之后调用方不再自己附 privacyMode / useCache，主进程门面每请求注入；留着它等于邀请谁「恢复」一道已经在下层执行的门，所以删了。
- 语言选择器记忆：最近的码驱动置顶区；字母是用户上次浏览的位置，只在记录时的 UI 语言下有意义（荷兰语在中文下归 H，Dutch 在英文下归 D）。
- `config.js`（localStorage 偏好）只留有真实消费者的字段：悬浮窗与流水线读 targetLanguage / sameLanguageBehavior / ocrEngine / ocrPriority / floatingOpacity / floatingDisplayMode。理解开关中立：它只让标 understandOnly 的动作出现，动作做什么由其提示配置决定（含用户导入的）。
- `session.js`（悬浮窗运行态，不持久化）：冻结面板需要 viewportPos——活面板存容器相对坐标，冻结面板用 position:fixed（视口空间），原样复制 bbox 会把面板按容器偏移瞬移；冻结上限 15 个 FIFO。

## 3. 划词窗（components/SelectionTranslator/）

- 校验：任何文字系统的字母 / 数字至少一个（西里尔、希腊、阿拉伯、泰文……），旧的字符类把所有非拉丁非 CJK 的受支持语言直接拒掉。超长单字符重复通常是 OCR / 编码垃圾，阈值放高，"哈哈哈…" 与 "====" 分隔线不被拒。跳过文件路径（盘符 / UNC / POSIX 绝对 / file://）。
- 窗口复用（hide 不 close），每个入口都要 `resetSession` 洗掉上一会话的状态（过期的 OCR 错误按钮、鼠标位置、在途翻译、还在说的 TTS），并递增代号让挂起的异步工作自行取消——过期结果永远盖不掉新触发。`adjustWindowToContent` 也有代号：后一次跑取代在途的，重叠的两趟不会争最终边界。
- Phase B 直通：主进程第三层已抓到的文本随载荷带来，点击图标优先用它而不是再 GET_TEXT 一次；用完置空免得泄漏到下一轮。点击 100 ms 防抖，快速 mouseup 不会误触发。
- 放置钳到**选择发生的那块显示器**的工作区（带原点），不是 `window.screen`（只有当前屏、没有全局偏移）。截图路径没有光标锚点——(0,0) 走 startDrag 分支保持主进程放的位置；截图那块屏的工作区也随载荷来，紧贴屏幕边缘截的图长大后仍钳在屏内。
- 实际翻译到的语言（同语言翻转之后）另存：历史元数据与 TTS 读它而不是配置的目标语言，否则翻转后的 ja→en 结果会配中文语音；直通标记 `passthrough` 也挡历史——未翻译的回声不是记录。AI 摘要读的是**配置的**目标：中文 + 「换回」开着时解析值翻成英文，摘要也会回英文。
- 测量不改窗口尺寸：强制内容元素宽度、同步读换行后高度、恢复。旧做法把窗口先放大到 maxHeight 当测量再缩回——每次切源文都有可见的先胀后缩闪一下。锚点 X 与顶部 Y 只算一次给测量与最终两趟共用，卡片不会在两趟之间水平漂移；只有 Y 在高度已知后细化（底部溢出翻到光标上方）。最终几何再做一次通用的离屏守卫：keepPosition / 截图路径锚在钳过的 28×28 加载点然后卡片**长大**，没有它扩张会在屏幕边缘溢出工作区。CJK 字宽约为拉丁的 1.6 倍。
- 覆盖层模式下只要有内容就调整窗口，哪怕译文为空：以 `(translatedText || error)` 做门曾让空结果跳过调整，窗口停在 40 px 的触发尺寸。`isFrozen` 经 ref 读、**不**作为依赖：冻结发生在拖动中途，那一刻触发的 adjust 会 setBounds 到操作系统的移动循环里、杀掉用户的拖动；冻结时内容没变，没有东西要调整。
- 统一自动隐藏（乙案）：每条覆盖层路径都在 triggerTimeout 后隐藏，悬停暂停倒计时（离开重排整个超时），冻结卡片豁免。
- 直通路径：主进程检测 CapsLock + 选择后直接推文本，跳过图标 UX（加载 → 覆盖层）但与图标路径共用设置 / 校验；`capturing` 阶段只挂加载点等后续 `translate` 消息；`from: 'hotkey'` 在历史里区分。
- 没有 settings-changed 监听：翻译栈在主进程、保存时自己重载，这扇常驻窗自动拿到新密钥 / 优先级；划词 UI 设置随每次显示的载荷到达。没有 keydown / ESC：窗口 `focusable:false`（故意——永不抢焦点），收不到键盘事件；关闭走右键、✕、点外、自动隐藏。
- 一次自动重试只针对瞬时网络失败，匹配两种语言的常见标记而不是单一子串；重试要转发覆盖语言，否则会静默退回状态值。
- 拖动检测：`-webkit-app-region: drag` 不触发 mouseup，轮询窗口边界；移动 > 10 px 冻结成独立覆盖层，下一次选择另起触发器；`adjustWindowToContent` 移动窗口期间持续重设基线，程序性的 setBounds 永不被读成用户拖动（那会在内容一变尺寸的瞬间冻住卡片）。冻结窗口由主进程按 ID 跟踪，用专用关闭通道；冻结卡片在冻结池里，`hide()` 只藏一个、留下看不见的点击捕获器——要正经关掉。钉住上限到了卡片保持活动并告诉用户为什么没脱离，而不是静默关掉别人钉住的内容。翻译完成时历史已记录（store 按 (source, result) 去重），冻结时再加纯属噪声。
- AI 动作读**选中的文本**而不是译文：理解在原文侧做、一步答成目标语言。源文与每个 AI 结果共用译文上方一个面板：打开一个关另一个，卡片最多长一块、只有一处可看；结果永远不是自己的卡片。
- 降级提示是瞬态的：视觉锁意味着它只出现在前两次截图，常驻横幅只会唠叨；显示后 3 s 自清（新提示重置计时）。错误载荷（加载看门狗超时）要显示出来——这个分支以前没有接收方。

## 4. 悬浮窗（components/FloatingWindow/、floating/）

- 纯 UI 壳，截取 / OCR / 翻译逻辑全在 `floating/pipeline.js`。默认 OCR 引擎（llm-vision）需要本地视觉模型，新用户没有会撞到这条路——关键字匹配触发「去 OCR 设置」按钮。
- **听译模式**为本窗口会话覆盖持久化的理解开关，离开听译恢复；模式入口按 ASR 模型是否在盘上把关（没有就零声明）。听按钮始终可见但灰到识别模型在盘为止，下载在设置页（用户裁定）；`refreshListen` 也在设置页装包后广播的 settings-changed 上跑，新下载不用重开窗口就点亮。
- AI 动作跑在识别出的源文上而不是译文——摘要的摘要会叠加翻译错误；配置了视觉模型时直接跑在截图上。每次截图都在跑的模式不再做成按钮——工具栏是给用户自选的事。
- 事件处理器在挂载时注册一次，闭包里的渲染态会冻在第一次渲染——读 ref。ESC 优先级：粘性穿透 > 历史面板 > 散落面板 > 关闭。Alt 是瞬时穿透（松开还原），keyup / blur 只结束**瞬时**保持，粘性模式必须活过两者（每次点穿都失焦正是它存在的理由）；blur 也退出 Alt 保持，否则 alt-tab 留它卡在开。
- 主题：IPC 握手 > store > localStorage。内容区边界轮询：布局变化（缩放、滚动条出现）不发事件。settings-changed 现在只带窗口自己的 UI 设置（栈与 OCR 重载是主进程内部事）；包可能刚装好，重新问而不是灰到重开。显示模式偏好改变立即对暂存的截图重排，切换不用重截就可见。工具栏 300 ms 延迟收起，鼠标滑出边缘一瞬不闪；粘性穿透下顶条保持可见——它是出口。
- **手动拖窗**：透明无边框窗上 `-webkit-app-region` 失效（E42，装机版也是），自己跟踪指针把位置流到主进程；交互岛（按钮、工具栏、透明度弹窗）排除。拖动意味着监视区域要变——停掉自动刷新（用户重新定位后再开）。抓取偏移用 window.screenX/Y 与 e.screenX/Y 同一 DIP 坐标系，与 setBounds 一致；**整段拖动锁定尺寸**（取一次）：每帧重推尺寸会累积分数 DPI 舍入，窗口越拖越大；锁定尺寸到达前的移动先扣着。
- 透明度用 CSS 变量 `--floating-opacity`，子面板保持不透明；IPC 只做窗口本地持久化，活过重启与设置广播。
- **自动刷新**：定时重截让实时更新的区域（Teams 字幕、视频字幕）免手翻译且窗口永不取焦点。用户规格：点按钮 → 选间隔 → 开始；移动窗口、手动截取、关闭都停（每次会话显式开始，永不自动恢复）。流水线里的静默去重让不变的帧零成本不碰 UI。间隔按 OCR + LLM 时延定——1.5 s 比一趟识别 + 翻译还快。全局热键重截在别的程序持焦点时触发，目标永不失去前台（相对窗内空格键的意义所在）。任何穿透状态下内容点击都属于下面的程序，绝不触发截取（旧的「误识别」投诉）；只有裸容器点击触发切换。
- **去重叠**：面板框（内边距 / 最小宽 / 译文）比锚定的 OCR 行框大，密集堆叠的块会产生不可读的重叠。一批落定（无面板 pending 或翻译中——尺寸那时锁定）后量真实渲染框，交给布局策略（`pane-layout.js`：只解决显著碰撞、最小双向位移、封顶漂移——贪心的一律向下曾把密集 UI 截图漂得很远）决定，每批只跑一次不与用户自己的拖动打架。锚定保真优于零重叠。
- 双击把散落面板脱离成独立 OS 窗口，主进程按文本长度定尺寸；BrowserWindow 创建失败（低内存）回退为内部冻结保持可用，冻结面板用视口坐标。
- **粘性穿透**：内容点击落到下方程序、顶条保持可点——转发的 mousemove 流按光标区域驱动 setIgnoreMouseEvents，只在越界时 IPC；与 Alt 保持不同它不需要焦点，所以活过它为之存在的点穿（漫画流：隔着覆盖层翻页，自动刷新重译）。
- 结果区徽章只在有信息时显示：自动模式（启发式怎么定的）与强制散落的回退（引擎没给坐标）；用户钉死的模式不需要回声。模式段（方案 A，用户选它而不是下拉）：三个常驻图标单选，没有弹窗可摸错；理解需要聊天 / 视觉源，听始终在但灰到模型下载完。听译状态文字自己一个元素——窄窗口截断的是**文字**而不是旁边的电平表。音源列表平铺、没有「除 X 之外全部」组：用户的裁定——选听什么是需求，排除某个程序不是；exclude 模式留在抓音层给 TTS 批用。选中的程序在刷新看不到它（暂停、曲间）时仍列出：值匹配不到选项的 select 会显示空白；U+25B6 标记「正在出声」——原生 option 放不了 lucide 图标，它是几何符号（默认文本呈现）不是 emoji。AI 结果折叠在译文下方而不是另开窗口——结果永远不是可再操作的东西。
- **ChildPane**：拖动状态用 ref 镜像，全局 mousemove / mouseup 闭包读 ref 不读过期状态；网页内容渲染不出 BrowserWindow 之外，钳到视口免得面板「丢」到边外，双击脱离才是把面板移出窗口的办法。坐标约定按状态不同：未冻结存父相对，冻结存视口。翻译完成即锁定尺寸，之后悬停不位移、内容更新不闪。最小尺寸地板收紧：词堆面板锚在词大小的框上，膨胀的框正是相邻面板重叠的原因。拖动 z 高于冻结与普通，冻结高于普通。
- **ListenLevel**：要点是时延不是装饰——文字要约 0.6 s（草稿）或句末后约 0.4 s（终稿），在此之前屏幕上没有任何东西告诉你声音到底来没来（「未检测到声音」要静音几秒才出现）。这条电平以音频回调自己的节奏（约 85 ms）动，是这个功能能诚实反应的最快速度，回答用户真正的问题「在播啊，为什么没动静」。rAF 循环读 ref 自绘，每秒十二次更新不重渲上面的字幕。落得比升快会显得跳，慢落读起来像表而不是频闪。**只有一种颜色**：试过「太安静无法转写」的着色又拿掉——阈值等于宣称 VAD 能听到什么，没有校准过的数字；长度已经把静音与信号分开，引擎自己的提示覆盖其余。gated（本程序 TTS 在播、抓音被丢）时变暗，平的一条读成「静音」而不是「没声」。
- **ListenPanel**：终稿按句末标点切（字幕短行规则）+ 译文，流式草稿是大的「正在播放」尾行；只有终稿到翻译——草稿按契约是临时的。会话状态在顶条（本来空着的拖拽条）不在这里，转写区给转写。每行朗读按钮（v0.4.2）悬停出现，任何窗口的播放都在 worker 里静音抓音（门），说出的话不会回来变字幕。最新的终稿在草稿在途时保持全强度——草稿只靠字号 / 字重压过它，把最新译文在句中调暗会藏掉正文。
- **useListenSession**：抓音**不在这里**（v0.4.1）——worker 里原生 WASAPI 把 16 kHz 单声道 float32 直接喂 VAD，删掉了这个文件的 getDisplayMedia、48k→16k 重采样、PCM 流与设备丢失重试环（音频客户端显式报设备失效，worker 重建并说明）。剩下：会话控制、终稿 / 草稿状态、来自 worker 的电平、经主进程栈的逐终稿翻译、SRT 装配。滚动回看故意小（100 行）：每段留着的都是活 DOM，没人在字幕覆盖层里回滚一小时。音源列表节奏：选择器只能显示已开音频流的程序，所以会话刚开始时密集刷新（接着通常是按播放），然后放慢，窗口被撂下后停掉——工具栏悬停唤醒。'source-gone' 几毫秒后就是 'listening'（worker 原地重开整机抓取），提示要挂够能读到的时间。音源选择**故意不持久化**：pid 只在那个程序运行时有意义，下次启动静默听继承了这个号的谁比每次从「整机」开始更糟；'system' 下带 pid 是留给下一个人读的矛盾。会话中切换源 / 语言重启 worker（语言烤在识别器配置里）——主进程归档到此为止的终稿、视图重来，与停 + 开完全一样（新 worker 时钟从零起，新旧行本就不能共享时间线）。离开听译模式（或卸载窗口）强停会话——引擎永不在没有宿主 UI 时空转（零闲置规则），主进程的 once('closed') 兜底硬关窗。
- **pipeline.js**：单飞——一次截取还在跑时再来一次会在截图中途把悬浮窗取消隐藏（IPC 处理器的透明度舞步）并交错会话状态。自动刷新 tick（keepDedup）**静默**跑到内容真变：不清面板、不进「截取中」态、去重键不动；旧行为每 tick 重置 UI，读起来像「上一次还没完就重新识别」；手动截取保留显式反馈并强制重 OCR 相同帧；静默 tick 失败不能每个间隔闪一次错误横幅。去重键包含目标语言**与**显示模式偏好：任一改变都要重跑，哪怕帧逐字节相同。理解按定义是整段的活，开关压过布局启发式：auto 会把密集截图判成「散落」，留下几个断开的气泡、没东西可解释。旧的 `session.addToHistory` 只写一个没人读的内存列表，悬浮窗翻译从没出现在任何历史视图里——现在转进主窗口的 store。引擎白名单由主进程门面注入，优先级按请求给（共享的管理器实例不能全局继承这扇窗的排序）。截图与它读出的文字配对，之后纯文本运行能知道图片已不描述会话（路径 B 不能读过期帧）。判定在原始逐行框上跑，面板粒度来自解析器（气泡合并段落、词堆用原始块）；截取帧与 OCR 框同一物理像素空间——稀疏覆盖规则（漫画气泡浮在图上）需要它。理解模式**替换**翻译步骤而不是叠加——用户要的是被告知这写了什么，不是换种语言读；结果是截图的主输出，记为自己的历史条目（kind 'understand'）而不挂在翻译上，除非动作以 history:'none' 退出；只存文本永不存截图——持久化截屏是新的隐私面。OCR 返回被截显示器的物理像素，CSS 要逻辑像素，优先截取时的 scaleFactor（自己的 devicePixelRatio 在混合 DPI 下可能属于另一块屏）。并发封顶 2：更多并发 LLM 调用在典型本地环境引起 UI 卡顿（每次调用短暂占住 GPU）。历史条目把所有面板合成一条，一次刷新 tick 一行。已是目标语言：显示原文、跳过翻译源与历史。
- **display-mode.js**：纯几何、无 store / IPC，启发式可单测。词堆（词汇表、UI 网格、漫画拟声）= 许多框近乎方形，段落行远宽于高，长宽比不读文字就能分「词」与「行」。图上的文字岛（漫画气泡、稀疏标签）= 块只占截取帧的一小部分，「清晰段落」截图会填满它。岛要就地气泡，哪怕单个气泡的行排成完美居中列；独立词要一词一泡，哪怕排成一列（旧的列测试把词汇表合成一坨）。纵向连续：段落行在约一行高内相继；对齐用中位偏差——对一行缩进或短行稳健，旧的相邻对距离一处缩进就翻车；左对齐段落与居中诗节都算一列。合并审计：库合并的块只在其原始成分看起来像一个视觉单元（对齐、宽度相当、紧密堆叠）时信任，列表行黏上邻居的徽章 / 序号会被拆回原始行；词堆完全跳过合并——逐词定位正是要点。框必须在读出它们的帧内：整组溢出说明那个坐标空间不是源图像素，按这些数散落会把译文贴到离原文很远的地方，不信任整组就退化统一模式（这些引擎报框之前的行为）；容差吸收边缘裁剪与舍入，不吸收 2× 的缩放错误。手动偏好压过启发式；散落需要有坐标的块——没坐标的引擎（LLM 视觉）回落统一而不是渲染零面板丢掉文字；`fellBack` 驱动徽章「引擎没给坐标」，auto 模式也举它：静默落到统一读起来像「启发式选的」，其实它根本没得选。

## 5. 文档翻译（components/DocumentTranslator/、document/）

- 设置在动作时读（挂载 / 解析 / 翻译）而不是订阅：设置页写 electron-store，每次动作新读即同步，不用重挂载或 IPC 监听。
- 进度持久化：解释也随同一 blob——它们背后是付费的逐段模型调用，关闭丢掉是真实浪费。loadProgress 只清用户重开的那个文件的键，被遗弃的文件会堆到约 5 MB 的 localStorage 配额直到 saveProgress 静默失败——所以有一次性过期清理。进度随累积持久化：0.2.9 之前只在一轮结束后写，中途崩溃或退出丢整轮（L2 磁盘缓存只有约 200 条，大文档没有安全网）；节流，快的翻译源不会每完成一段就序列化整个列表；批量解释掉笔记与翻译掉段落一样快，同一节流。安全模式污染要活过模式本身：段落状态在用户离开安全模式后仍持有安全期文本，那时写一次就冲到盘上；新解析解除污染——但安全期文本也活在内存翻译缓存里，缓存命中会把它直接放回可持久化状态，两个一起清。
- 语言状态自持，从主 UI 播种但可分叉；源允许 auto、目标不允许；与主面板同一目录，含自定义条目——用户加的语言到处都该看到。
- 搜索：`-1` = 尚未定位，Enter / Next 到 0、Prev 到末；matchIds 由 query + segments 经 useMemo 派生，翻译中段落流入时不重置光标，只在查询本身变化时重置。Ctrl+F 有可见性守卫（组件在其他页签后面保持挂载）。
- 「用 T-Translate 打开」与选择文件走完全相同的路（密码提示、扫描页 OCR、进度恢复）；消费回调清掉父级槽位，同一个 File 对象不能再触发；故意只以 externalFile 为依赖：loadFile 的身份随设置变化，不能重跑加载。笔记按段落 id 键、id 每个文档从 0 起，新文档会继承上一个的解释——加载路径必须清。
- 工作池而不是合并批：每段自己的成功 / 错误状态，失败项不会像合并批响应那样冒充完成；并发默认低——本地 LLM 在 GPU 上串行，更多在途只是排队（与 pipeline 散落模式同一校准）。暂停 / 恢复：计时从 startTime 派生，恢复时把纪元前移暂停跨度，否则暂停时间算翻译时间。
- AI 动作：共享 hook 围绕一个活动段落，只取能力探测与可用性过滤；笔记本身在 use-segment-notes 里同时活着多条。文档面没有理解开关——问一段就是请求，代表动作自行选择加入。可解释的段落：被跳过的（页码、代码块）没有东西可解释。笔记按文档顺序而不是打开顺序读成走一遍文档。「一键」= 先逐段解释再把解释汇总，逐段过程正是摘要负担得起的原因——模型从不一次看整篇。摘要范围说清楚：它是对读者打开过的段落的笔记，不是对文档的；两条笔记起才值得一趟往返——一条笔记本身就是笔记。
- 词汇表一致性只管一种情形：模型留在源语言的术语；译成别的词的不报（见 term-consistency）。`fixes` 活过模态关闭：段落里的标记是读者之后交互的东西，每个要知道自己的替换前文本才能撤销。撤销一处：从未动过的文本用剩余术语重算，三处的段落撤一处另两处原样。两侧都标（源文英文、译文替换后的中文）成对可见。无模型参与，只要有术语且有译文就提供。术语弹窗锚在被点的标记上、fixed 定位（滚动列表拖不走）。
- 文件名是攻击者可控的（资源管理器右键能打开任意文件，名字也是）：作为 React 子节点渲染、永不 dangerouslySetInnerHTML，`<img onerror=…>.pdf` 被转义而不是执行。
- **解析器**（`document-parser.js`）：MAX_FILE_SIZE 限的是**压缩后**文件；zip 容器（EPUB / DOCX）可膨胀约 1000 倍，20 MB 能解到几 GB 把渲染进程 OOM——右键菜单能打开任意文件后这是一键 DoS，所以也限解压总量：声明大小来自 zip 中央目录（便宜、不解压）但可伪造，EPUB 读取器在 JSZip 解压时（校验 CRC）再套运行时累计上限；mammoth 没有解压上限还建内存 DOM（再放大一次），跑之前先查 zip 声明大小。PDF 渲染比例钳住，荒唐的 MediaBox 不能分配巨型画布（宽×高×4 字节），永不放大超过 2；比例 2 让小字对本地 OCR 可读且内存不膨胀。零散项（页码、水印）仍算扫描页。SRT id 顺序编号而不是文件的 cue 号——真实文件会重号或重复，撞 React key 与进度恢复映射，原 cue 号存 `index`。`FileReader.readAsText` 只认 UTF-8；老中文字幕 / 小说常是 GBK，有些 Windows 工具出 UTF-16——按证据解码：先 BOM，然后 UTF-8 除非 GBK 的替换字符严格更少。时间码原样保留，VTT 载入导出 SRT（或反之）要换毫秒分隔符——播放器与 `<track>` 解析器拒绝错的；SRT 要两位小时字段。EPUB 属性顺序因生成器而异，分别提取而不假设 id 在 href 前；实体用 fromCodePoint（数字实体可能是星光平面）。用户错误（不支持的格式等）打标签，日志里当用户失误记而不是抢注意力的程序错误。pdf.js 的拒绝可能没有消息——报错要说是哪个文件哪个阶段。
- **术语一致性**（`term-consistency.js`）只报模型留在源语言的术语，遗漏是故意的：译成别的词（词汇表说词元、模型写令牌）在这里既不可修——字符串里没有东西说哪段本该是那个术语——也无关紧要：这个程序是让读者抓大意的，不是按专业术语标准审校；一张「自己去看这五段」的清单是校对工作，而更好的模型正在让这种工作越来越少。留下的是确定的、即时的、总能操作的。术语必须在该段源文里出现过，否则一个恰好活到译文里的英文词会被改写成它从来不是的术语。撤销时从未动过的原文重算。
- **词汇表 IO**：容忍中文字段名（原文 / 译文 / 备注）以兼容其他工具的导出；CSV 加 BOM 让 Excel 按 UTF-8 打开；TBX 用正则解析（无 DOMParser，Node 测试也能跑）。

## 6. AI 动作（ai/、config/ai-actions.js）

- 动作是**数据不是代码**：字段说明可出现在哪、当前源能否运行、提示怎么建、结果可存哪。导入的动作（`normalizeActionConfig` 校验）与内置走完全相同的路；程序只带框架加两个中立内置。占位符在导入时校验，拼错的 `{{sorceText}}` 大声失败而不是原样送给模型。
- 「看 vs 懂」：'translate' 动作属于阅读（开关关），'understand' 属于理解模式（开关开），'any' 两者；没有开关的面视作关。文档也是阅读面：译完仍看不懂的一段说明书与截图一样不透明；没列进去导入的文档动作会在导入被拒而内置的能用。理解开关本身不决定任何事——它挑装了的那个 'understand' 动作，做什么由其提示配置定，导入的配置能整个替换行为而不碰程序。
- 长文门：CJK 字符与拉丁单词分开计——150 个汉字与 150 个英文单词内容量差很远；任一刻度过自己的杠即可，混合文本（引英文的中文文章）不必两个都过。用户只调一个数：拉丁杠按内置默认的比例（150 字 ≈ 120 词）跟随。散落内容是几个断开的标签，没东西可总结，入口藏起来；理解开关开着时窗口不再翻译，也没东西可并列总结。模型读源文侧、一步答成输出语言——译文的摘要会叠加它的错误。
- 路径 B 优先（视觉模型直接看截图）：它看得到版面，不会丢给 OCR 错误或识别器错序合并的文字；看不了图的模型（或端点挂了）不能让用户付出动作的代价——识别文本已在手，路径 A 收尾。带 vision 提示的动作即标记为可直接跑在截图上，措辞要变因为没有 `{{sourceText}}` 可贴。
- 回答语言：钉在提示的语言而不是 i18n 当前语言，提示永不把英文语言名混进中文包装；语言名读共享的 134 语目录而不是 i18n——`languages.*` 只有 16 条，其他目标以裸码到达提示（"write the summary in it"），模型答英文；未知码原样返回是故意的——用户自加语言把面向模型的名字**作为**码存。每个动作带中英两套提示按 UI 语言选：错语言的包装会把弱模型拉去用那种语言作答。`requireChat` 让 AI 动作不落到把提示翻译一遍的 chatCompletion 兜底——翻译成的指令看起来像功能正常。模型爱用围栏或引号包散文，剥掉。结果窗显示的是哪个模型看了用户的屏幕（'llm-vision' 是引擎 id）。
- AI 结果是内容的衍生物，遵循与历史相同的规则：安全模式那半在 store 的 addToHistory 旁边（一道门管两个，子窗口经它写），配置这半——标 'none' 的动作归模块自管、任何模式都不进主历史。
- 导入的动作配置在 electron-store 里，**每次读都重新校验**：config.json 是用户能手改的普通文件，运行时不信任导入门没查过的东西；三扇窗与截取流水线都要同一份列表所以缓存，`refreshImportedActions()` 是设置保存钩子。
- 「汇总」故意**不是**全文摘要：它只看到用户选择打开的段落，叫摘要就是撒谎——200 页说明书解释了三段会产出「三段难点的摘要」；真正的全文摘要要对每段做 map-reduce，那是流水线不是提示。它是便宜且诚实的：map 阶段已由读者自己的点击付过，输入是几条笔记而不是一本书，读得越多越完整。文档有自己的进度文件从不碰历史 store，所以没有翻译条目可挂。
- `use-ai-actions`：阈值在使用时读而不是挂载时——设置页在同一渲染进程，刚改的阈值该对下一次按键生效而不是下次启动；按原始字符串缓存，JSON 每次真变才解析一次。每个动作一个结果，与产生它的文本一起记住，新翻译永不显示上一段的摘要；身份是段落**与**作答语言——只按文本键曾让切换目标语言后一直交回旧答案，摘要永远停在上一种语言。栈重载时重新探测：设置里加了 LLM 源或导入动作要不重启就点亮入口。路径 B 要事先说明截图本身要被发出——图片泄漏的远比路径 A 的一行文字多。第一次点击运行，之后的点击把结果折起 / 展开——与卡片的源文切换相同，且结果永远不能成为另一次运行的输入。
- `use-segment-notes`：笔记同时在 ref 与 state 里，`explain` 不会每落一条就变身份——它传给每个 memo 的 SegmentItem，长文档的批处理否则每完成一条重渲全部。批处理在翻译源明显不再回答时放弃，而不是对整篇每段发一个注定失败的请求；一批一个报告，死掉的源不能每段弹一个 toast。恢复路径已有笔记优先——读者刚做的不能被晚到的旧 blob 覆盖；非字符串丢弃（blob 是可手改的 localStorage）。
- 收藏 / 保存流程的分析提示：两个组件曾各带一份逐字副本（收藏那份只有中文），合成一处；提示按 UI 语言切换让 LLM 用用户语言返回标签；中文指令包装非中文文本会把弱模型拉去用中文回答。

## 7. 设置页（components/SettingsPanel/、ProviderSettings/）

- **默认表**（`constants.js`）：只有全局（OS 级）快捷键可配置——应用内键（翻译 / 交换 / 清空 / 粘贴 / 复制）曾可在 UI 编辑但没人读 settings.shortcuts，面板里写死，行是纯装饰，已删。`interface` 桶以前只靠 electron-store 构建期默认从顶层展开漏过来——全新安装或全部重置让它 undefined，InterfaceSection 读 .theme 崩溃，现在这里拥有形状。文档桶是唯一来源——0.2.9 之前漂成三套不相交的键、每个控件都是死的；0.2.9 按翻译器真正读的键重塑，旧键（preserveFormatting / batchSize / maxParagraphLength…）从未被消费，batchMaxTokens 属于从未实现的合并批设计，batchMaxSegments 映射到 concurrency 保住唯一活着的用户意图。悬浮窗默认与 `electron/ipc/floating-window.js` GET_SETTINGS 的兜底必须同步。saveHistory / maxHistory / cacheEnabled / maxCache 是幽灵键：持久化了几个版本从没被消费（历史上限在 translation-store.historyLimit，缓存上限在主进程栈）。TTS 默认的唯一来源是 `tts/index.js`（`electron/state.js` 保一份值相同的副本——主进程不能 import 渲染端 ESM）。LLM-Vision 端点原是孤立的 `settings.connection.endpoint` 桶（无 UI），迁移时把这个活值带进 `ocr.llmEndpoint`（timeout / model 是死的），无条件丢掉旧桶——老安装也带着旧默认播种的空 `{}`。`floatingWindow.lockTargetLang`（2026-07-10 退役）：ON 意为「永不翻转 zh↔en」，统一行为里就是 'original'；OFF 用户拿到新默认 'original' 而不是 'swap'——翻转现在经 `sameLanguageBehavior` 选择加入。'paddle-ocr' 引擎 id 已从注册表删除，不重映射旧持久值会让 OCR 永久失败（回退链不覆盖未知的首选引擎）。0.2.9 之前隐私管道的死键要删，否则 privacy.mode 永远经 settings.privacy 的保存往返。摘要阈值随程序出货只是估计，本就该按真实文档调——现在由用户调，一个数、拉丁杠按比例派生。
- **面板**（`index.jsx`）：一个对话框实例在面板层传给各节，五个覆盖层没意义。`useShallow`：设置常驻在其他页签后面，没有选择器每次流式刷新都重渲整个面板。脏桶跟踪：save() 只写脏桶，不会用过期的内存快照重新持久化未动的桶——翻译桶尤其关键，它的配置是懒解密的。**没有 beforeunload 守卫**：Electron 把关窗拦成隐藏、退出时直接销毁不派发 beforeunload，它从没保护过任何东西——而返回字符串会静默**取消**菜单的 Reload；页脚「未保存」指示是诚实的信号。「音频」从两张卡开，除非经搜索点名了一侧：听译 / 识别词落到听，朗读 / 语音词落到读。先把保险库之前的明文 OCR 密钥搬进 safeStorage，下面读的桶已经干净；运行态（平台 / OCR 可用性 / 划词开关）永远压过持久值；初始化标志延迟清——子组件（尤其 ProviderSettings）要约 100 ms 加异步解密才落定，它们的初始写不能把面板标脏。保存按节做 dot-path 写，并发更新者碰兄弟字段不互相覆盖（读-改-写竞态）；翻译源数据从父级镜像持久化（ProviderSettings 初始化时把解密配置镜像上来），任何页签的保存都保住源编辑而不是旧的按 activeSection 路由的路径把它们丢掉；只在真编辑过时——未动的翻译桶否则会剥掉它从没收到的键。加密失败保持脏让用户修好加密后重试。语言键归 sync-to-electron 镜像，把整桶的加载快照写回会两个都覆盖。保存默认透明度意味着用户在显式设置它，丢掉窗口本地覆盖（GET_SETTINGS 优先 floatingWindowLocal.opacity）否则永远遮住它。API 密钥进 safeStorage 永不进明文桶，加密失败密钥从盘上丢掉（不保存）——要说出来。**全部重置**要清每个旁路存储不只 electron-store——主题、语言、侧栏偏好、zustand 偏好、OS 自启都在 'settings' 键之外；引导标志也是旁路——留着它们会交给用户一个从不打招呼的「出厂新机」；zustand 持久化的偏好字段与历史 / 收藏共享一个 store，按字段重置不抹键；API 密钥**故意保留**（确认框说明）——清掉会逼用户重新获取，隐私页的「清除所有数据」是全抹的出口；重置后从新加载重建，运行态（OCR 可用性、划词开关）重新检测而不是裸默认快照。
- **界面节**：三个即时生效控件（主题 / 语言 / 快捷键）自己持久化，React 状态静默更新——否则面板对已保存的更改显示「未保存」。主题传播四步：本地 state → `<html data-theme>` → localStorage（刷新 / 截图窗口读） → 主题 IPC 广播。全局快捷键先向 OS 注册，处理器成功后持久化，成了才（静默）镜像到 React 状态；被拒的组合不能留在状态里等着被写。裸键劫持规则与主进程一致（F1–F24 可裸绑）。
- **OCR 节**：BASE_PACK_ID / HQ_PACK_ID 必须与 `electron/shared/ocr-packs.js` 一致（渲染端不能 import 主进程模块；manifest 可能列其他代际的基础包，id 必须精确）。进入页面轻量检查（文件存在），深度（建 ONNX 会话，约 0.5 s 主进程停顿）只给显式动作；只在用户实际用本地引擎时自动检查。手动重选 llm-vision 清掉自动降级锁（锁在主进程栈，三扇窗全局）。语言选择器按首字母分组，语言需要的包放 tooltip 而不是 `<optgroup>`。渲染助手不做内联组件：渲染体里定义的组件每次按键都是新身份，React 会重挂载输入丢焦点。
- **听译 / 朗读节**：听译节是 ASR 模型**唯一**的下载入口（用户裁定 2026-08-28）；高精度档要语音槽可用（`llm:status` 的 `asr.usable`）才能选「高」，否则提示先放模型、档位不动；语音包手放，设置页给官方与镜像链接、打开文件夹、重新扫描，没有下载按钮；旧 sherpa 高精度包只在已安装时列出、供删除。引擎在下次会话开始读存储的档位，没有热切换；档位是「高」而语音槽不可用时（删了包、换了机器），控件下面直说这次按标准档跑——管理器照样静默回退，控件不能说谎。悬浮窗缓存「听译可用吗」，装完要让它重问。模型的实际位置不总是下次下载落的地方：v0.4.0 前装的包仍在旧 userData 里照常工作。朗读页（批 4 设计）：启用开关、引擎分段、一行「正在用谁说」状态（本地 vs API + 预览按钮）、引擎自己的块、三个滑块一行。卸载时归还状态槽（并停掉试听），否则主面板的状态回调在访问这页后一直被逐出。sherpa 语音与 OpenAI 语音路由没有音高输入。密钥直接进 DPAPI 保险库（`tts_endpoint_` 前缀：离线模式封其解密）永不写进设置。一次真实合成是唯一诚实的连通性测试，样本播放让用户听到服务器的真实声音。神经语音按语言选，不经单一 id；一个说话人覆盖双语的包（MeloTTS）算能读。语音选择器替换长下拉（kokoro 带 103 个）：搜索框、分段过滤、三个一行的分组芯片各带预览，选中即生效。
- **翻译源设置**（`ProviderSettings/`）：新装默认表——旧规则 `enabled: index === 0` 按显示顺序，而顺序以 OpenAI 开头（列表里唯一没有付费密钥什么都做不了的），新安装恰好有一个启用源且永久不可用——只要设置页持久化了列表（任何页签的任何保存都会），此前栈落到 DEFAULT_PRIORITY 悄悄能用，坏法像「改了个设置翻译就不工作了」。本地模型领先云端兜底：LM Studio / Ollama 在跑文本不出机器，没在跑 localhost 瞬间失败（拒绝连接不是超时），免费无密钥的 Google 作答；内置模型最前：文件在就零配置作答，不在就瞬间失败（无模型）链零成本前进。等设置从盘加载完再初始化，否则用默认覆盖已存配置；只在种子无值时才从保险库拉——页签重挂时 savedConfigs 已带用户未保存的编辑，旧的解密会用盘上密钥覆盖它；解密配置镜像给父级（静默：加载时同步不是用户更改）。updateSettings 故意不作依赖：父级每次渲染都换身份，会无意义地重跑解密循环。离线仍拦显式测试点击——门在主进程门面。只在折叠时可拖——否则 HTML5 拖拽拦截输入框内的 mousedown，点拖选字失效。内置模型卡片显示模型自己的名字（白名单文件已装且源开着），否则通用名。schema 的 select 目前都只有几个选项，分段控件合适；长列表需要选择器。`persist.js`：加密全部密钥再动盘（全有或全无），密钥不会在保存报成功的同时被静默丢掉；一次性迁移把旧 localStorage 明文搬进 safeStorage 后抹掉，迁移失败也抹——明文不能留；主进程栈自己重读 store + 保险库，没有明文配置跨 IPC 回来，三扇窗同一次重载。
- 关于页：GPU 开关（v0.4.9）一个开关、在 OCR 宿主里自检、显卡真建了会话才生效，宿主即时换提供器不要求重启；更新检查阶段 errorMsg 只在模态里渲染而模态没开——没有 toast 这个失败看不见；旧包先列（清除按钮只在搬完后出现，700 MB 模型永不一键消失）。隐私节：PRIVACY_MODES 存图标名字符串（配置文件保持纯数据），这里解析成 lucide 组件；文档翻译续传 blob（dt_progress_<fingerprint>）带译文——单列出来可见而不是埋在总数里；导出迁移包读**持久化**的设置而不是面板内存副本——面板把 OCR 密钥解密进输入框，那些不能进可分享的文件；导入按桶 dot-path 写，包里没有的桶保留本地值而不是被整键写抹掉。

## 8. 配置表（config/）

- **语言目录**（`languages.js`）由渲染端（选择器）与栈（建提示）共享——service.js 已 import config/filters.js，纯数据跨这条线是既有做法；一张表让选择器永远不会提供提示构建器叫不出名字的语言。范围 = Google Translate 支持的：Google 默认启用、无需密钥，google-translate.js 把未映射的码原样透传，每一条开箱即用不需逐源映射；覆盖更窄的源（DeepL）拒绝做不了的，链前进。字母索引跟随 UI 语言（中文读者在 H 找荷兰语，英文读者在 D 找 Dutch），中文侧要拼音首字母：按字符键而不是按语言——100 个字符覆盖全部 134 个名字，新语言通常以已有字符开头；`check:languages` 在名字以未映射字符开头时失败；`scripts/bench/verify-google-languages.mjs` 让 Google 试译每个码，加条目后跑它而不是肉眼信一个码。按字母键的偏好在 UI 语言变化时要丢——同一语言落在不同字母下。
- **自定义语言**：内置目录是 Google 的集合，到这里的都是 Google 做不了的（方言、少数语言、用户为它加载了专门本地模型的）；只有 LLM 源有机会，成不成全看模型。**码就是提示名**：每个 LLM 源以 `LANGUAGE_CODES[code]?.name || code` 建指令，自定义码落到码本身——把面向模型的名字作为码存，不用往栈里接任何管道就能让提示正确。两个名字答两种读者：name 给选择器（用户自己的语言），promptName 给模型（也是码）。本地模型可能认「藏语」不认 Tibetan，或反之，只有加载它的人知道。码原样承载名字——不 slug、不折叠大小写，冲突同法比较；内置优先，自定义永不遮住已验证的语言。
- **模型语言覆盖表**（`model-language-coverage.js`）：故障转移链只在失败时前进，而 LLM 被问不会的语言不失败——它产出流利的胡话并报成功，LM Studio 在前 Google 在后的用户永远到不了 Google 翻藏语。**只用于重排链**，永不用于灰化、过滤、警告或在 UI 上做任何声明：模型名不可靠（微调、量化重传、本地重命名），公开的语言列表偏保守，每条都是有良好先验的猜测——「先试 Google」可以，作为对用户的陈述不诚实。约束正是让失败模式安全的东西：无规则匹配 → 不重排 → 完全是今天的行为；错误匹配 → Google 先 → Google 反正翻；正确匹配 → 长尾跳过小模型 → 更好。这里没有东西能让程序比没有它更糟，保持这样。值：数组 = 文档集合、'many' = 广覆盖永不降级、缺失 = 未知永不降级；故意不完整，只在公开覆盖清楚稳定时加一族。opus-mt-en-zh 只做 en→zh，别的返回自信的垃圾，是表里最有价值的一条。稳定重排永不丢人：降级的源在前面全失败后仍会跑。
- **MT 模板映射**：按名字识别仅翻译的 MT 专家模型，栈切到 user-only 提示 + 简化指令，避免小 MT 模型（聊天模板不认 system 角色）常见的提示泄漏；语气仍生效。规则匹配家族不匹配版本（`/\bhy[\s\-_]?mt/i` 捕获 Hy-MT2 / 3 / HyMT4），版本特定的模式下个版本就过期。
- **OCR 语言表**（`ocr-languages.js`）：每条都对着包自己的字典文件核过，内置基础包还跑了真识别——不是对着上游文档，它两个方向都错了。入选规则是**书写系统**在场而不只是文字系统：越南语排除——看起来像普通拉丁、字典有 ă â đ ê ô ơ ư 但没有一个叠加声调，真跑返回 "Tôi đang hc ting Vit" 置信 0.985，声调全部静默丢失、读起来像正常文本译成胡话；希腊语同理——字典有 76 个希腊字母（作数学符号）但没有带重音的；蒙古语、哈萨克语、塔吉克语从西里尔包排除（没有 ө ү ғ қ ң）；乌兹别克语从基础包排除（oʻ gʻ 是能产字母，okina 缺失）。乌克兰语（缺 ї）与马其顿语（缺 ѓ ѕ ќ）保留：几个字形出错远好过根本不提供。表由 `electron/shared/ocr-packs.js` 的 LANGUAGE_TO_PACK 镜像，`check:languages` 防漂移。OCR 设置区分两种中文文字，共享目录讲翻译、区分的是地区。
- **过滤器**：无 logger import——被主进程栈交叉 import，core/logger.js 带 Vite 专有的 import.meta。版本号过滤器要 `v` 前缀或三段：裸 "0.3" 是小数不是版本，把 "0.3 秒" 变占位符曾让小本地模型当 OCR 错误改写。用户过滤器同名覆盖默认。
- **模板**：模板 = 语气（自然 / 精确 / 正式 / OCR），消息结构（system+user 或 user-only）由主进程栈按活动模型决定；名字 / 描述 / 图标元数据从未被用，UI 标签走 i18n。**图标目录**：svg 是 Vite import，主进程栈打包绝不能看到，所以在渲染端合并；显示顺序沿用退役的渲染端注册表（预设在前、独立源在后），设置列表不重排。

## 9. 核心、共享件、朗读与 i18n

- **错误处理**（`core/error-handler.js`）：「没有可用的翻译源」是最常见的首次运行失败，以前落到 UNKNOWN（「操作失败：发生未知错误」）零指引。类型键必须是 ERROR_TYPES 的值（'api_quota' 不是 'quota'），否则 formatError 的查找永远找不到。分隔符按语言——写死的全角「：」在英文 UI 上读成混排标点。全局错误处理：`error` 带栈；message / line / column 三件套只指向打包后的列号谁也用不上。
- **日志**（`core/logger.js`）：在这里压成字符串而不是跨 IPC 送对象——结构化克隆丢掉 Error 的栈（唯一值得要的部分），主进程不该重新序列化渲染端递来的任何东西。warn / error 镜像到主进程日志文件：渲染端输出以前只有控制台，React 崩溃、未处理的 rejection、window.onerror 在盘上没有痕迹——每一个都得现场复现才看得到；永不抛、永不等待。链式 `??` 是死代码：`NODE_ENV === '...'` 永远是布尔。
- **迁移包**（`core/migration-pack.js`）产品侧两条硬规则：无 API 密钥（持久化设置已无密钥——密钥在机器绑定的 DPAPI 保险库——但构建与导入都再剥一次，手改的 config.json 或旧安装不能把密钥漏进可分享文件；schema 声明的加密字段先剥，名字模式扫描兜住运行版本没有 schema 的源）；无模型二进制。术语形状与独立词汇表导出一致，两种文件互读。
- **流式节流**（`core/stream-throttle.js`）：token 每秒几百个，每动画帧最多发一次（按设备档位地板）封住下游 setState / 序列化；Chrome 把 deviceMemory 钳到 8，">= 8" 是顶档（16 GB 机器也报 8）。流落定后调用方**必须** cancel()：终稿套用后再触发的 flush 会用过期半截覆盖它；窗口隐藏时 RAF 停发——缓冲输出等终稿，正是「没人看就不渲染」。
- **系统通知**：只在窗口隐藏或最小化时发（窗内 toast 已覆盖可见情形），且 `interface.systemNotifications` 开着（undefined 算开）；Electron 无条件授予渲染端通知，权限检查只对浏览器开发态有意义，那里跳过而不是弹权限提示。
- **文本工具**（`core/text.js`）：「是不是已是目标语言」不在这里判，由 `stack-client.detectLanguage` 问主进程（规则见 `docs/design/stack.md` 第 8 节）；这里的 `detectLanguage` 只是同步的按文字类型判断，给 AI 动作与悬浮窗理解记录标原文语言。同语言行为：'original'（默认）显示原文不调翻译源；'swap' 翻回用户配置的源语言——**不是**写死的 zh↔en（旧启发式误导非中英用户）；源为 auto 时没有另一边，zh↔en 作兜底。判不准（null）时两种行为都去翻译：'original' 只在确定时显示原文，'swap' 只要不确定是别的语言就互译。两种行为在不同时间都被要求过（翻转 2026-06-10，直通 2026-07-10），所以成了设置 `sameLanguageBehavior`，划词窗与悬浮窗共用。两个字母以内的英文通常是噪声（UI 缩写）。
- **引导**（`core/use-onboarding.js`）：标志在 electron-store 而不是 zustand persist——它是应用级状态，随全部重置一起清，与翻译内容无关，清历史的用户不该再被欢迎对话框迎接。每次读默认「已看过」：答不出的 store 不能让欢迎框在第一百次启动时出现；少显示一次是非事件，多显示一次是用户停不掉的烦扰；读不了的 store 也写不了，现在显示的提示会每次启动回来、关闭按钮无效。提示气泡（`OneTimeHint`）只用在设计点名的两处：每个控件都提示会让首次启动到处弹东西，训练用户不读就关——然后真正有用的两条也被关掉；关闭永久，回来的唯一路是全部重置。欢迎框只说能做什么、从哪开始——不配置任何东西；在用户知道自己买的是什么之前就要密钥的首跑向导正是它故意不做的；装配提示是常驻条而不是 toast，因为它是持续状态不是事件，栈重载有可用源时自清；就绪未知时不渲染——因为还没问就说「翻译没配好」是对最没能力分辨的用户撒谎。
- **可见性守卫热键**（`core/use-visible-hotkey.js`）：页签面板在非活动页签后保持挂载（display:none），裸 window 监听器会在全应用吞键——这类 bug 发过三次（DocumentTranslator Ctrl+F、HistoryPanel 方向键、MainWindow 幽灵搜索）才集中到这里；display:none 的祖先让 offsetParent 为 null。
- **语言选择器**（`shared/LanguagePicker.jsx`）：原生 `<select>` 在 134 条时不行了，改成面板——最近用的置顶，每个字母一节，索引条可点可按住拖。索引跟随 UI 语言；芯片显示 UI 语言的名字不显示自称——没有搜索框只能靠眼睛，`አማርኛ` 对中文读者没意义而「阿姆哈拉语」有，自称放 tooltip。'auto' 不是语言、不属于任何字母组。用户自加语言自己一个置顶区而不是字母组：它们的「字母」是用户敲的名字首字，曾把一个孤零零的「藏」挂在 A–Z 条末尾。offsetTop 相对滚动容器，节标题落到顶部没有 scrollIntoView 拖动中的动画延迟；scrollTo 不通用（jsdom 没有，旧嵌入引擎也没有），丢动画好过在点击处理器里抛错。面板比触发器宽得多，靠右的触发器（文档翻译器标题栏、窄窗口）会把它推出屏幕——打开时测量而不是按断点猜。重开回到用户浏览处——但另一种 UI 语言下记的字母指向不存在的组。按住拖是触屏习语鼠标用户不会发现，只能是加分项；每个字母自己的点击处理而不只靠条的命中测试——拖动路径从指针坐标解析字母，普通点击不能依赖它。自定义语言的码就是提示名，会在两字母标签的槽里渲染成整个词，虚线框已表示「自定义」，槽留空。
- **高亮**（`shared/HighlightText.jsx`）：历史与收藏曾各带一份近似副本（收藏那份没有 memo 也不处理正则敌意输入）。最后一道防线：非字符串（0.3.x 空翻译 bug 的散落结果对象）交给 React 会抛 #31，store 在 rehydrate 时修复，这里让渲染路径活过漏网的。最长优先：包含另一个的术语必须赢，否则短的把它劈开两个都渲染错。只有术语标记可交互。确认对话框（`ConfirmDialog`）替代 `window.confirm`（阻塞渲染线程、无视主题）。
- **朗读**（`tts/`）：管理器多监听器——单槽曾让最后订阅的组件静默逐出其他的（设置一打开主面板状态就死）；引擎的 updateConfig 以前没有定义，第一次带活引擎改设置就抛 "updateConfig is not a function"。web-speech 是零下载地板：始终在，配置的引擎丢了语音包能诚实降级而不是报错；回退时**不动** `_config.engine`，用户的选择保留，`_refreshConfig` 每次 speak 重试，包一回来引擎就回来；逐句回退：神经包读不了这门语言（或丢了文件）把这句交给系统语音而不是失败，配置引擎不变、下一句覆盖的语言又走神经。每次 speak 前重读持久化配置：这扇窗（尤其常驻的划词窗）可能持有首次初始化的旧快照，store 是真相、设置保存写它。每次状态变化驱动听译静音门。神经引擎：PCM 随 chunk 到达就在一个 AudioContext 上排程，第一句就开始播而不是等整段；小前导让第一个缓冲不排在过去；rate 映射为 sherpa 生成时的速度（比播放重采样音质好），sherpa 不支持 pitch；voiceId 是系统语音的选择（或按语言语音之前遗留的神经 id），神经语音只按语言选所以故意不传；`decodeAudioData` 会分离缓冲，复制一份让重试能复用；新 speak() 静默取代（面板播放 / 停止切换靠 SPEAKING 保持），只有 stop() 宣布 IDLE。语音挑选（`tts-voice-pick.js`）：中英混句——kokoro 的中文说话人读英文口音重，MeloTTS 正是在这种文本上训练的，标 preferMixed 的包胜出；显式选择只要其包能读这门语言就是最终的，中文专属包被要求读日文落到自动。Web Speech：语音列表异步、Electron 最糟要重试几次（等 3 s voiceschanged、之后短暂轮询、再试一次）；拉丁文字细分——以前全落 'en'，西班牙 / 法 / 德文由英文语音读；一档近乎独占的标记（土耳其集合故意无 /i：有了它无点 ı 会折叠到普通 I，每句英文都匹配），二档共享重音按频率猜（芬兰 ä/ö 落 de、无 ç / 抑扬符的法语可能落 es，都好过一律英文）。挪威语语音是 nb-NO / nn-NO，'no' 前缀匹配找不到，那条映射是承重的（不像 pl / cs / tr 的地区标签都以裸码开头）。取消 + 微延迟——在活动话语上叠着说在 Chrome / Edge 是竞态；越界值在某些引擎上静默失败，钳到规范范围。外部端点引擎：请求在主进程栈里跑（系统代理、保险库密钥、离线门），这边只要字节并播放。
- **OCR 密钥库**（`ocr/ocr-key-vault.js`）：在线 OCR 密钥必须像翻译源密钥一样进 safeStorage，永不进明文 settings.ocr；键名 `ocr_<flatField>`——`ocr_` 前缀是离线门匹配的；清空值也删保险库条目，删掉的密钥不会下次启动复活；加密失败的字段仍剥掉（明文永不写）、调用方要报错；解密返回 null（离线门、无 DPAPI、无条目）让引擎未配置，这是正确的失败模式；一次性迁移只在加密成功后剥字段——无 DPAPI 机器上旧明文继续可用（祖父条款），只是拒绝写新的。图片哈希（`ocr/image.js`）每 100 字节采样，「和上一 tick 同一张截图」的廉价判断，非密码学。
- **听译文本**（`listen/listen-text.js`）：流式草稿引擎（zipformer）出大写拉丁文，SenseVoice 终稿片刻后换成正常大小写；草稿短暂一生里把喊叫降下来，一行不在 "LEVEL MEETING" 与 "Level meeting" 之间闪；混合大小写的草稿不动；四个字母以下是缩写（OK、USA）不是喊叫。
- **i18n 词表**：同一命名空间只能有一个块——重复键静默覆盖前一个（解析器的 epubNo* 查找曾死了几个版本）；英文串必须保留 error-handler ERROR_PATTERNS 匹配的关键字（not configured / invalid / timeout / quota / connection failed）；latin 包已并入 base-v6，键保留让残留的已装副本卸载前仍显示正常名字；内置 AI 动作的显示文本在这里，导入的动作自带标签没有键。

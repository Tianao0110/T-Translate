# 工具脚本设计说明（scripts/）

代码：`scripts/check/`（门禁）、`scripts/build/`（栈打包、模型发布构建、运行时覆盖）、`scripts/fetch/`（OCR 基础模型、llama 运行时、模型来源表）、`scripts/smoke/`（Electron / worker 冒烟）、`scripts/bench/`（听译基准）、`scripts/lib/`（共用测试件）。用法在各脚本头部；这里记「为什么这样做」。

## 1. 门禁（check/）

- `check-constants`：两份常量表（主进程 CommonJS、渲染端 ESM）必须同步，比较前剥掉行注释与尾逗号。
- `check-i18n`：把 ESM 词表改写成 vm 能跑的 CommonJS（去 `export default`、`const xx = {}` 改 `module.exports`），vm 解析失败时用正则兜底抓平铺键值；主进程 i18n 与渲染端词表一起查。
- `check-languages`：目录只在一处（`src/config/languages.js`），剩下的漂移在边缘——命名常量枚举与各传统翻译源自己的码表。翻译源合法地支持**子集**（DeepL 没有泰语）；反过来，翻译源映射了一个程序根本提供不了的码才是真错误。命名常量不是目录镜像，只列代码里字面写的那几个（AUTO、ZH），不变量是「子集」不是「相等」。OCR 语言表故意存在两份（引擎在主进程解析包、设置下拉在渲染端渲染、渲染端不能 import 主进程代码），必须**相等**：只在一边的码要么是 UI 提供而引擎错路由，要么是引擎认识而没人能选。抓码表时要取**定义**而不是第一个调用点——google-translate.js 在定义前 90 行就调了映射器，从调用点切片曾把请求头当语言码扫进来。中文字母索引读名字首字的拼音首字母，未映射的字会静默落到 '#' 组，没人会去那里找。
- `check-hardcoded-chinese`：扫描栈之外的所有用户可见代码（栈带中文兜底是设计）与引擎宿主。基线门：历史遗留的高优先级项冻结在 `hardcoded-chinese-baseline.json`（键是 file::text 不带行号，无关编辑不会挪动它们），超出基线的退出 1——新代码必须走 i18n；`--update-baseline` 只会把文件收得更紧，永不接受新发现。基线用正斜杠让任何 OS 上字节相同。三档：错误（用户可见 UI 文本）、警告（可能需要 i18n、值得人看一眼）、跳过（注释、日志、i18n 源文件）。
- `check-docs`（v0.5.2）：文档里指到的东西必须还在——以 `src/`、`electron/`、`scripts/` 等顶层目录开头的路径、`npm run` 的脚本名、相对 markdown 链接，三样逐个对仓库。起因：2026-09-18 查文档过时，主题文档的「注册主题」步骤已经对不上界面，OCR 文档的行号链接指到了别的函数，sherpa 说明里的脚本路径还是分目录之前的。**它只抓「指到的东西没了」，抓不了「说法不对了」**（步骤数、个数、界面叫法），那类要靠发版前人工过。故意不扫 CHANGELOG 与 TODOS：它们讲的是过去。gitignore 的产物（`electron/generated`、`resources/`）CI 上不存在，按前缀放行；指南里「你的新文件放这里」式的虚构名字登记在脚本的 `EXAMPLES` 里。同一轮还试过「文档里反引号标识符在源码里找不到就报」，噪声太大（DLL 名、外部 API 名、历史叙述），没留。**说明书的界面叫法**（v0.5.2 加的第二条规则）：中文说明书里的「…」、英文说明书里的 "…" 引的都是界面上的字，逐个到对应语言的词表里找，找不到就红；主进程的原生菜单与对话框（`main-i18n.js`）、托盘（`tray-labels.js`）、资源管理器右键菜单（`installer.nsh`）也算来源，引号里是说明书自己的小节名也放行，带「→」的当菜单路径跳过。实测中文 81 处引用全中，英文 69 处里有 12 处对不上——几乎全是大小写（界面是 `Test Connection`，说明书写 `Test connection`），还有两个听译模型名写的不是界面上的名字。比对用的是词表源文件的原文，不解析 JS，够用且不会因为词表结构变化而坏。

## 2. 构建（build/）

- `build-stack`：用 esbuild 而不是 electron-vite / vite-plugin-electron——那些会接管整个开发 / 构建流水线，这个仓库只需要「ESM 栈 → CJS 文件」（gstack 设计稿 main-process-migration-design-2026-07 §2.1）。`electron` 标为 external 是**绊线**不是功能：栈源码直接 import electron 是设计违规。
- `overlay-sherpa-runtime`：把能上 GPU 的 sherpa-onnx 运行时覆盖到 npm 包的纯 CPU DLL 上（Windows x64），postinstall 与打包前运行。覆盖的是 `sherpa-onnx-c-api.dll` / `sherpa-onnx-cxx-api.dll`（来自 native/sherpa-onnx-webgpu/bin，sherpa-onnx v1.13.7 加 `webgpu` 提供器补丁，配方在那个目录的 README）与 `onnxruntime.dll` / `dxcompiler.dll` / `dxil.dll`（来自 onnxruntime-node——唯一带 WebGPU EP 的预构建 ORT，官方 NuGet / GitHub 构建不带）。为什么是覆盖不是 fork npm 包：addon（.node）仍是上游的，只换它链接的 C-API DLL 与加载的 ORT；addon 在自己旁边解析这两者，所以副本必须放在 sherpa 包目录而不是 PATH。按 sha256 幂等；未动过的原件保留一份，`--restore` 与干净 diff 不用重装。覆盖针对的 addon / ORT 版本写死：不同版本意味着 DLL 要重建而不是复制。
- `build-ocr-release` / `build-audio-release`：manifest 条目不带 url / 源路径，客户端自己拼 baseUrl + file。OCR manifest 里旧代际条目排在前面：v6 之前的客户端用 `find(type === 'base')` 选基础包，base-v5 必须先于 base-v6。音频包：Node 没有 bzip2，上游 .tar.bz2 先手动解压到 `%APPDATA%\t-translate\asr-models`，脚本从已解压的本地副本**重新打包**成平铺 zip，每个文件来自哪个上游制品记进包内 PROVENANCE.txt，一年后重建就是下载 + `tar -xjf`。`--only` 只重建指定包，其余保留已有 manifest 的条目，从另一棵源树重建语音包不会把 ASR 包挤出 manifest；两边都没有的包丢弃并警告而不是编造。语音包带整棵目录（`tree` 源），按相对路径打 zip，程序的解压器原样保留。zip 条目用固定时间戳，同样的输入永远得到同样的 sha256——重跑并 diff 能验证某个资产确实由这些文件构建；每棵树一行 provenance（排序后 (name, hash) 列表的哈希），树内改动或缺失文件也会改变记录。发布步骤（每次模型更新手动一次）：GitHub 建草稿 Release、tag `ocr-models` / `audio-models`、**标 Pre-release**（否则 electron-updater 把它当最新版本）、上传 release-*-models/ 全部内容、发布；之后更新模型只需在来源表里 bump `version`、重跑、替换变化的资产与 manifest.json。
- `wait-for-vite`：原生 HTTP 轮询代替 wait-on。

## 3. 取包与来源表（fetch/）

- `fetch-llama-runtime`：Vulkan zip 是 CPU zip 的超集（同样的 llama / ggml DLL 加 Vulkan 后端，b10853 上逐字节验证过），一次下载覆盖两种后端。从 zip 里只取 C API、多模态助手、ggml 核心、每个 CPU 变体（运行时挑选）、Vulkan 后端、OpenMP 及其许可证；tools、server、rpc、llama-common 不要。GitHub 每个发布资产有 sha256 digest，钉版时当第二意见；之后的取包只信 manifest 的哈希。
- `fetch-ocr-models`：下载内置基础 OCR 模型到 `resources/ocr/base`，写与包管理器同形的 pack.json。
- `ocr-model-sources`：上游是 eSearch-OCR 的模型存储 Release（Apache-2.0，由官方 PaddleOCR 模型转换）。v6-small 是单模型 50 语言，暴露的子集是对着字典核过的（越南语、希腊语为何缺席见 `renderer.md §8`）。高精度变体不进安装包、不是语言包，用户在 OCR 设置的档位控件里选择加入。旧代际条目（base-v5、latin 包）为 v6 换代前发布的程序保留：它们的基础包修复解析 'base-v5'，fr / de / es 仍映射到 latin 包；**永远别 bump 或改这些**——旧客户端的引擎对 gen !== 'v5' 开启空格启发式，绝不能收到 v6 模型。上游把卡纳达语叫 "ka"（格鲁吉亚语的 ISO 码），按字典核过不是按文件名。
- `audio-model-sources`：上游是 k2-fsa/sherpa-onnx 的预转换模型 Release。**同名不同源的陷阱**：同一上游 tag 上 2025-09-09 的 `sense-voice` 包是 ASLP-lab 的粤语特化微调（把每种语言都判成粤语、日韩文乱码），`sourceDir` 钉住经过检验的 2024-07-17 原版，构建拒绝打包别的。基础包 = 终稿引擎（标点 + ITN）加 VAD：VAD 随包而不是独立包，因为每条路都需要、只占下载量 0.3%，未来换基础模型也会带自己的。角色 → 文件名的 map 取代了 `electron/listen/asr-models.js` 里写死的文件名：换模型改 map 不改代码。两遍草稿引擎可选，缺则草稿退化成伪流式（从终稿引擎回放 partial）照样能用——永远别拿它做听译模式的门槛。高精度终稿引擎（v0.4.8）Qwen3-ASR 0.6B 是 LLM 式解码器：音乐、说唱、噪声下远比 SenseVoice 稳（带 BGM 的歌实测 CER 7.8% 对 95.6%），覆盖 31 种语言，驻留约 1 GB，CPU 上 RTF 约 0.2；只在用户选档时替换终稿，VAD 仍来自基础包。它的 ONNX 导出是第三方的（Wasser1462 的脚本，权重在 ModelScope），由 sherpa-onnx 重新打包，2026-09-07 的 spike 端到端验证过；更新的导出换入前同样对待。词表目录 sherpa 按路径打开 vocab.json / merges.txt。手放同样可达：上游 tarball 解压到 `asr-models/<QWEN3_ASR_DIR>` 没有 pack.json 也能解析；程序在 `electron/shared/audio-packs.js`（MANUAL_PACKS）带同一条目，单测保证两处一致；从此超过 400 MB 的包带 `manual` 不带 `file`——只给链接不上传。这个 sherpa 高精度包现已退役：高精度档改由 T-Engine 语音槽出定稿（GGUF 包在 `electron/shared/llm-packs.js`，见 listen.md §4）；manifest 与 MANUAL_PACKS 里的条目留给旧版程序和删除旧包用，别删。神经语音包（v0.4.2）同一 Release、同一 manifest、不同根（tts-models）与管理器；带整棵目录。**int8 在这里是负优化**：x86 上实测比 fp32 慢 4 倍、加线程无收益（onnxruntime 反量化开销），两个包都带 fp32 权重。Kokoro v1.1-zh 103 个说话人：0–1 美英女、2 英英女、3–57 中文女、58–102 中文男，这一代没有英语男声；英语经 espeak-ng 音素化（GPL-3 数据随包），中文经 jieba 词典 + 词汇表；精选的几个在选择器里展开，其余在「全部语音」后面。MeloTTS zh_en 单女声在中英混合文本上训练，中途切换语言读起来自然，渲染端对混合文本优先它；不需要 espeak-ng；同一速度值下中文比 kokoro 快约 20%（22 字 4.18 s 对 5.09 s），0.9 按耳朵定，英文已是正常语速。

## 4. 冒烟与基准（smoke/、bench/、lib/）

- 共用件 `electron-smoke.js`：argv、PASS / FAIL 清单、一次性 userData + 模型根沙盒（必须在 require 任何主进程模块**之前**调用——state.js 加载时就冻结 store 路径）、模型文件硬链接（同卷）或复制进沙盒、假 electron-store、把清单变成退出码的运行器。Chromium 到退出才关会话文件，rm 失败不算测试失败，下一次跑的 rmSync 会清掉。
- `smoke-listen`：SAPI 语音对 VAD 与 SenseVoice 来说是真语音。两个坑：PowerShell 脚本以 `-EncodedCommand`（UTF-16LE base64）传，中文走普通 argv 会被弄坏；合成器以原生 22050 Hz 渲染——向 SAPI 要 16 kHz 会用这些 Desktop 语音写出静音文件（验证过 maxAbs 0.000）。时延从声音真正开始算不从文件开头算（SAPI 开头约 100 ms 数字静音）。离线门拒的是**网络**访问，而整个测试件跑在 file:// 上（本地读取不是网络），所以拒绝要对着真实用户拿到的 URL 形状检查：第二个管理器、同一道门、https manifest，两条网络路径都必须在任何 fetch 之前拒绝——注入的 fetch 一旦被调用就抛。原生抓音（v0.4.1）：回环客户端只在端点上有渲染流活动时收到包——完全静音的机器什么都不给（2026-09-02 实测 0.00 s；之前的绿色跑有浏览器或程序在播），所以检查从隐藏窗口自己渲染一个近乎静音的音调，帧计数证明 koffi 装载、客户端激活、格式被接受、泵在跑、stop() 能停；信号本身不制造噪音就无法断言。喂音按固定起点调度，睡眠漂移不算引擎时延；`source 'off'` 不开音频客户端由测试件自己喂 wav。段起点只能向前——曾经不是：强制切分调 `vad.reset()`，sherpa 自己的段时钟随之归零，之后每个自然关闭的段都从新原点报起点，长会话的 SRT 时间线倒着走。高精度档在 `models/asr-gguf`（或 `--asr-dir`）里有语音包时测，可选：经真实的 llm-manager 起语音宿主（`--gpu` 上显卡），同一段 wav 必须全由宿主出定稿；再注入三次停滞把宿主标成不健康，定稿必须改由标准档引擎出、日志记 `hq-fallback`。引擎替换对 worker 之上的一切必须不可见。同一段音频再去掉草稿引擎跑一遍，这是只装基础包的用户实际看到的。神经 TTS：worker 以 TTS-only 起（无听译会话）、逐句流、按需换包、取消时中途停、换包 / 删除前释放包。GPU 语音需要 WebGPU 运行时覆盖，没有它 sherpa 在 stderr 报回退、自检如实说而不是装作成功。`--soak` 在一个会话里回放 N 分钟报告 worker RSS 趋势——回答「听几小时会不会涨」。
- `smoke-offline`：所有网络原语换成绊线，任何一个被碰到就失败；捕获 IPC 处理器而不是注册——处理器就是渲染端能到达的那个函数，用假 event 调。
- `smoke-ocr`：整屏尺寸的截图是模型主导墙钟的地方，CPU / GPU 对比在它上面量；死掉的宿主不能让程序搁浅，下一次调用重生。
- `smoke-llm*`：`worker-driver.js` 从纯 Node 驱动 runtime worker（一个 worker、请求 / 响应配对、逐请求 token 累积、共享 abort 标志）；栈级冒烟把白名单文件以钉定名硬链接进沙盒让扫描器的哈希检查生效；视觉宿主冒烟用 BMP 头加原始 RGB 位图，mtmd 的 stb 加载器够用不需要编码器；GPU-only：CPU 上管理器在读包的第一个字节之前就拒绝、设置卡显示不可用。语音冒烟用 `electron/tengine/runtime/assets/asr-health.wav`（自检同一句）加可选的 FLEURS 句子；语音槽 CPU 也接活，宿主冒烟显卡与 CPU 各识别一遍。
- `bench-listen`：FLEURS（google/fleurs dev，CC-BY-4.0）每种语言 N 个不同句子按间隔拼接、实时回放过真实链（VAD、AGC、切分、两个引擎、看门狗），打分覆盖率、CER（zh）/ CER + WER（en）、每句终稿数、终稿时延——2026-09-02 基线就是用它量的，做成脚本免得随 scratchpad 消失。评分口径与基线文档一致：参考用 FLEURS 的 normalised 列；zh 去空格与标点再算 CER；en 小写、去标点与撇号再算 CER 与 WER；终稿归到重叠最多的句子，没有终稿的句子算未覆盖、整句参考计为删除。`--normalize` 把每段裁到统一 rms（0.05，AGC 自己的目标）再拼，测的是链本身而不是 FLEURS 的电平跳变。每次跑一个沙盒，两种语言可并排。状态越过 starting > listening > stopped 说明宿主中途死过又回来，时钟重启，之后的终稿落错句、时延无意义。`--tier high` 经语音宿主出定稿（`--gpu` 上显卡），结果另带 `hqFallbacks`（回落到标准档的段数）与 `hqRequests`（宿主每段的耗时）；CPU 上机器别有重活，别的进程抢核会让段排队超时、整批回落，量出来的是机器不是链。
- `verify-google-languages`：目录里约 134 个码程序里没有东西能验证，错码不抛——google-translate.js 原样透传，拼错只会永远静默地回未翻译文本；这是唯一知道表是真的办法。一次性、**不在** check:all 里——每种语言向 Google 的非官方端点发一个请求，改目录后跑。'en' 是样本自己的语言，Google 理所当然原样回显，否则会读成无效码。
